## 安装和身份确认

1. 按 [INSTALL.md](INSTALL.md) 选择 main 源码试用或精确提交的成功 CI 候选包；两者的证据级别不同，不能视为已发布版本。
2. 校验 SHA256SUMS；解压后在独立 Edge 配置中加载解压扩展。
3. 检查 `BUILD_INFO.json` 的 `source_commit`、产品名和版本均匹配；确认 ChatFlow 0.3。记录候选包和安装后文件的校验结果。
4. 不覆盖旧研线/ThreadLine 扩展，不清理旧扩展数据。ChatFlow 与旧扩展使用独立存储，不会自动迁移。

## A. Archive Engine

使用不含敏感信息的测试对话，预置早期/中间/末尾可验证事实，并包含 PDF、XLSX、CSV、图片、用户上传文件和助手生成文件。

1. 明确选择已打开的普通 ChatGPT 对话，点击保存；核对来源 ID、可见消息、活动分支、替代分支和文件状态。
2. 抽样比较原始文件 SHA-256 与档案实际字节；分别核对用户上传和助手生成文件。
3. 测试过期/不可访问文件、重复文件名、来源不明文件、来源分支无法映射文件；不可用状态不得被标为 saved。
4. 导出 ZIP，独立解压并验证 `chatflow.archive/2` 清单、`conversation.json`、`conversation.md`、assets 和 SHA-256；附件有 `parts` 时按清单顺序重组并校验整文件。再恢复到另一份独立浏览器配置，原档案不得被覆盖。检查清单中的应用版本为实际安装的 0.3。
5. 关闭并重新打开浏览器，确认持久化数据和文件字节仍在；未完成的任务必须显示 interrupted/unknown，不得静默重放。
6. 分别测试 all 与 last_generated 保存范围；后者仍保存完整正文/分支，只保存当前活动分支最后一份可确认助手生成文件。无法判定时 fail closed。

## B. Context Builder

1. 选中至少两份本地档案，默认当前分支，生成上下文 ZIP。
2. 核对 `context_manifest.json` 中来源档案 ID、conversation/message/node ID、快照哈希和完整性状态。
3. 选择全部可访问分支及关键词过滤，确认只有符合规则的消息进入分段。
4. 故意设置低 token 预算，确认内容完整分段并告警，不静默截断。
5. 默认不带入附件；显式勾选附件后，核对 ZIP 中实际字节与 SHA-256。
6. 真实上传上下文包后，用早/中/末事实和附件指定值测试新对话；模型回答正确不能证明全部内容已读，记录实际验证范围。

## C. Parallel Experiments

1. 开启并行实验开关，创建 K=2 实验，冻结共同材料 W0 和任务 P；核对冻结文本哈希。
2. 发起两个普通新聊天，核对两页预填文本逐字相同，且没有自动发送。
3. 人工逐个发送；观察每个会话 ID 与分支 attempt 绑定，避免结果串线。
4. 手动触发采集；只有精确输入、完整持久化、助手回复非空且 finished 标记可证实才可标记 done。
5. 关闭一个分支或重启浏览器，确认状态变为 unknown/恢复状态，不自动重发。
6. 所有分支完成后生成盲测对照；裁决前不显示分支映射。完成校准后人工裁决并揭盲。
7. 再测试 K=3、K=4，确认分支数限制、tab 绑定和结果隔离。

## D. 安全边界

| 场景 | 预期 |
|---|---|
| 已有草稿/文件 chip/旧对话/Project/Temporary | 拒绝注入，保留原内容 |
| 页面身份变化、tab/document 不匹配 | 停止，状态 unknown/failed |
| 上传观察超时或状态不明 | 交还控制权，不自动重试 |
| 目标模型是否读取附件 | 标记无法证明，不推断成功 |
| 删除本地档案 | 只影响本地记录/共享 Blob 引用，不修改源对话 |

## E. 记录模板

只记录脱敏信息：

- 提交 SHA、artifact SHA-256、浏览器版本、操作系统、设备配置、测试日期和参与者匿名编号。
- 用例 ID、执行前状态 `pending`、实际结果（pass/fail/unknown）、错误代码、关键状态转换；未执行不能预填 pass。
- 文件类型、字节数和 SHA-256；不记录文件正文。
- 首次用户的原始回答、是否得到额外提示、实际点击及结果；性能记录库规模、冷启动/重复操作耗时和失败情况。
- 不上传 ChatGPT 对话 JSON、真实附件、Cookie、Token、签名 URL 或未脱敏截图。

真实账号测试未执行时，状态必须保持 `pending`；不能用合成浏览器测试替代。

## F. 源自 PR #1 阻断缺陷的真实账号补充验收（按 0.3 更新）

仅在独立 Edge 配置中用虚构数据执行；每条记录测试操作、预期、实际状态及脱敏错误码。

1. K=2、K=3、K=4：在冻结任务预填后，分别检查手动发送、ChatGPT 新会话原生单页路由、后续采集及每个分支的来源身份，不应发生错误归属。
2. 在预填后、发送前，主动导航到另一个旧会话；不得允许其成为当前分支回复。原分支应保持未完成/unknown，不得自动重发。
3. 在发送后、采集前切换到另一个会话，或令页面完整重载造成 documentId 变化；不得采集或判定 done。
4. 在采集进行中切换会话并返回；迟到的采集回执不得让原分支变成 done。
5. ZIP 正常往返与恶意压缩尺寸、压缩比超限样本分别验证。使用一个 **65 MiB** 已保存附件，在整份归档总量允许时导出 `chatflow.archive/2`；核对其分成 64 MiB + 1 MiB 两个条目，在独立配置恢复后整文件大小和 SHA-256 一致。缺块、错序或篡改的样本必须被拒绝且既有档案不变。
6. 构造所有条目累计展开大小**超过 256 MiB**的档案，正文、清单、诊断和不重复附件字节均计入。确认导出在提供下载前明确拒绝，本地内容仍保留；外部超限 ZIP 恢复同样拒绝，原有 IndexedDB 档案数量、身份和字节不变。保留单条目 64 MiB、压缩比等安全限制，不通过提高上限使样本过关。

历史方案将“单文件超过 64 MiB”列为拒绝条件，反映旧格式的恢复缺口；0.3 改为附件分块，64 MiB 约束的是 ZIP 条目，不能继续把合法 65 MiB 附件判为不支持。总量超过 256 MiB 仍不支持，不能将分块描述为任意容量备份。契约见 [ARCHIVE_FORMAT.md](ARCHIVE_FORMAT.md)。浏览器发起下载不等于落盘成功，必须检查实际下载文件并执行恢复。

以上均是**待执行真实账号验收**，未获真实独立测试证据不得写成 pass。人为测试和 L3 Stop Gate 仍需单独完成。

## H. Saved Passages（始于 0.2）— 0.3 后置复验

保留 CF-11 至 CF-15 的历史追踪范围；仅在本轮 0.3 工程实现和自动化门禁完成后执行。当前未执行，不请求用户提供登录凭据。

1. 在真实已登录 ChatGPT 档案中选取不同消息、相同重复文本、跨段落文本和多分支文本，验证本地片段的来源 messageId/nodeId。
2. 在包含多分支的真实对话中切换当前路径与其他可访问叶分支，分别验证历史正文、重点片段高亮、来源跳转、Context Builder 和接续包使用同一条所选路径；断开或不连续的节点路径必须被拒绝。

4. 对目标消息追加新消息但保持原消息不变，确认 passage 仍可恢复；修改或移除原消息，确认 stale/ambiguous 状态而非静默跳转。

7. Context Builder 分别使用完整消息、仅重点片段、混合模式；核对 passage manifest 回链、附件范围、关键词过滤、预算分段和 stale/ambiguous 阻断。
8. 由实际使用键盘、屏幕放大或屏幕阅读器的真实参与者执行选择、保存、重新定位、跳转、删除及上下文选择；记录焦点、朗读标签、状态播报和错误恢复，方法见 M 节。

## I. 首次 Edge 实测问题专项复测

以下用例针对 0.2 首轮真实 Edge 测试发现的问题，操作预期已按现行 0.3 原生侧边栏修订；自动化覆盖不替代本机复测。

1. 打开一条普通历史 ChatGPT 对话，在没有待领取并行实验的情况下，确认页面不出现“并行分支预填未确认（NOT_NEW_NORMAL_CHAT）”提示。
2. 从已保存档案点击“继续到新对话”，进入准备页；点击“准备历史与文件”后，再点击“打开新对话”。确认新聊天在当前 Edge 窗口中以新标签页打开，原始对话与 ChatFlow 原生侧边栏仍保留；不得额外创建 Edge 窗口或第二个工作区标签页。
3. 确认新标签页为空白普通聊天后，接续材料逐字预填，附件按校验结果上传；发送仍由用户手动完成。
4. 在新聊天标签页关闭后回到原 ChatGPT 标签页及 ChatFlow 侧边栏，确认“继续到新对话”为主操作，“重新采集对话”和备份为次操作。保存失败但保留旧快照时应突出“重试保存”，不能引导执行不可用的接续操作。
5. 点击“重新采集对话”，确认相同来源、相同保存范围更新原档案；档案数量不增加，既有已保存文件不丢失。更换保存范围时应创建独立档案，不得静默改写原档案的保存范围。
6. 再次打开接续流程，确认旧接续状态不会错误地被新任务复用；来源身份不符合普通新聊天时，显示明确错误且不自动重试。

## L. 至少 5 名独立首次用户验收

当前未执行。最终候选至少需要 **5 名未参与设计或开发的独立首次用户**。给出要完成的任务，不演示点击路径，不额外解释界面。让每位参与者在下列关键状态先指出“下一步点哪里”和“点了会发生什么”，再实际操作，逐项保留原始回答与观察结果。

| 关键状态 | 应能识别的下一步及结果 |
| --- | --- |
| 首页与首次保存 | 找到保存入口，识别所选来源与范围，知道保存对象是哪段对话 |
| 保存完成 | 找到“继续到新对话”，知道将进入准备流程；不会误认为返回原聊天或重新采集 |
| 接续准备完成 | 区分“准备历史与文件”和“打开新对话”；知道最后发送仍由自己完成 |
| 下载中、部分保存与失败 | 知道当前能否备份、备份包含什么，以及何时应该等待或重试 |
| 任务已复制 | 知道把任务文本交给 Agent，完成后从哪里回传结果 |
| 结果已保存 | 找到“复制结果并返回原对话”，能指出来源，知道回到原对话后仍需自行粘贴、核对和发送 |

**任一参与者在任一关键状态答不出或理解错误，先记为失败，修改布局或按钮文案，再验该状态。不能靠追加说明段、主持人提示或培训把失败改成通过。** 修订后由尚未看过该版本的首次用户复验，最终候选保留至少 5 名独立用户的完整记录。得到额外讲解的尝试只能作为问题诊断，不计入首次使用通过证据。

通过后仍只报告该样本和版本的结果，不推断所有用户均能理解。开发者自行点击、合成自动化和原型截图不计入这 5 人。

## M. 真实辅助技术参与者验收

当前未执行。由实际使用相应辅助技术的真实参与者操作候选扩展，记录所用浏览器、操作系统、屏幕阅读器/放大工具及版本；开发者可排查问题，但不能替代参与者完成验收。

1. 键盘完成保存、接续、任务发出/回传、备份恢复和重点片段操作；核对焦点顺序、可见焦点、展开收起、错误后的焦点与恢复路径。
2. 屏幕阅读器辨认来源对话、文件状态、当前主操作和不可用原因；动态进度、保存结果、超限及错误提示能被感知，周期刷新不能抢走焦点或重复播报无变化内容。
3. 使用屏幕放大及参与者常用的文字缩放设置，检查浅暗主题、长标题、输入提示和窄屏重排；关键内容与按钮不得被遮挡或依赖颜色单独表达。
4. 在剪贴板拒绝、超长输入、部分备份和失败重试时完成替代操作；核对已输入正文仍可访问、来源关系可辨认。出现阻断即记录失败，修复后由相应参与者复验。

自动化的标签、对比度、焦点检查仅是工程证据；它们不能使本节变成已执行或已通过。
