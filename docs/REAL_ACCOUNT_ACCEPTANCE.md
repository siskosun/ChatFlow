# ChatFlow 0.2 真实账号验收方案

本文是待执行验收方案，不是已通过报告。真实登录账号测试必须由所有者在独立浏览器配置中执行；不需要也不应把账号凭据交给云端开发环境。

## 安装和身份确认

1. 只从准确提交 SHA 的成功 GitHub Actions `chatflow-candidate` artifact 取得 Edge 包。
2. 校验 SHA256SUMS；解压后在独立 Edge 配置中加载解压扩展。
3. 检查 `BUILD_INFO.json` 的 `source_commit`、产品名和版本均匹配；确认 ChatFlow 0.2。
4. 不覆盖旧研线/ThreadLine 扩展，不清理旧扩展数据。ChatFlow 与旧扩展使用独立存储，不会自动迁移。

## A. Archive Engine

使用不含敏感信息的测试对话，预置早期/中间/末尾可验证事实，并包含 PDF、XLSX、CSV、图片、用户上传文件和助手生成文件。

1. 明确选择已打开的普通 ChatGPT 对话，点击保存；核对来源 ID、可见消息、活动分支、替代分支和文件状态。
2. 抽样比较原始文件 SHA-256 与档案实际字节；分别核对用户上传和助手生成文件。
3. 测试过期/不可访问文件、重复文件名、来源不明文件、来源分支无法映射文件；不可用状态不得被标为 saved。
4. 导出 ZIP，独立解压并验证 manifest、conversation.json、conversation.md、assets 和 SHA-256；再恢复到 ChatFlow，原档案不得被覆盖。
5. 关闭并重新打开浏览器，确认持久化数据和文件字节仍在；未完成的任务必须显示 interrupted/unknown，不得静默重放。
6. 分别测试 all 与 last_generated 保存范围；后者仍保存完整正文/分支，只保存当前活动分支最后一份可确认助手生成文件。无法判定时 fail closed。

## B. Context Builder

1. 选中至少两份本地档案，默认当前分支，生成上下文 ZIP。
2. 核对 `context_manifest.json` 中来源档案 ID、conversation/message/node ID、快照哈希和完整性状态。
3. 选择全部可访问分支及关键词过滤，确认只有符合规则的消息进入分段。
4. 故意设置低 token 预算，确认内容完整分段并告警，不静默截断。
5. 默认不带入附件；显式勾选附件后，核对 ZIP 中实际字节与 SHA-256。
6. 真实上传上下文包后，用早/中/末事实和附件指定值测试新对话；模型回答正确不能证明全部内容已读，记录实际验证范围。

## C. Parallel Experiments

1. 开启并行实验开关，创建 K=2 实验，冻结共同材料 W0 和任务 P；核对冻结文本哈希。
2. 发起两个普通新聊天，核对两页预填文本逐字相同，且没有自动发送。
3. 人工逐个发送；观察每个会话 ID 与分支 attempt 绑定，避免结果串线。
4. 手动触发采集；只有精确输入、完整持久化、助手回复非空且 finished 标记可证实才可标记 done。
5. 关闭一个分支或重启浏览器，确认状态变为 unknown/恢复状态，不自动重发。
6. 所有分支完成后生成盲测对照；裁决前不显示分支映射。完成校准后人工裁决并揭盲。
7. 再测试 K=3、K=4，确认分支数限制、tab 绑定和结果隔离。

## D. 安全边界

| 场景 | 预期 |
|---|---|
| 已有草稿/文件 chip/旧对话/Project/Temporary | 拒绝注入，保留原内容 |
| 页面身份变化、tab/document 不匹配 | 停止，状态 unknown/failed |
| 上传观察超时或状态不明 | 交还控制权，不自动重试 |
| 目标模型是否读取附件 | 标记无法证明，不推断成功 |
| 删除本地档案 | 只影响本地记录/共享 Blob 引用，不修改源对话 |

## E. 记录模板

只记录脱敏信息：

- 提交 SHA、artifact SHA-256、浏览器版本、操作系统。
- 用例 ID、结果（pass/fail/unknown）、错误代码、关键状态转换。
- 文件类型、字节数和 SHA-256；不记录文件正文。
- 不上传 ChatGPT 对话 JSON、真实附件、Cookie、Token、签名 URL 或未脱敏截图。

真实账号测试未执行时，状态必须保持 `pending`；不能用合成浏览器测试替代。

## F. PR #1 阻断缺陷的真实账号补充验收

仅在独立 Edge 配置中用虚构数据执行；每条记录测试操作、预期、实际状态及脱敏错误码。

1. K=2、K=3、K=4：在冻结任务预填后，分别检查手动发送、ChatGPT 新会话原生单页路由、后续采集及每个分支的来源身份，不应发生错误归属。
2. 在预填后、发送前，主动导航到另一个旧会话；不得允许其成为当前分支回复。原分支应保持未完成/unknown，不得自动重发。
3. 在发送后、采集前切换到另一个会话，或令页面完整重载造成 documentId 变化；不得采集或判定 done。
4. 在采集进行中切换会话并返回；迟到的采集回执不得让原分支变成 done。
5. ZIP 正常往返与恶意压缩尺寸、压缩比超限样本分别验证。特别确认单文件超过 64 MiB 或累计展开超过 256 MiB 的档案会被明确拒绝且原有 IndexedDB 档案不受污染。
6. 对大附件用户说明：ChatFlow 可以保存部分大字节文件但 0.1 的 ZIP 恢复存在资源上限。若使用场景依赖超限 ZIP，请记录为当前版本不支持，不能通过人为提高上限解除。

以上均是**待执行真实账号验收**，未获真实独立测试证据不得写成 pass。人为测试和 L3 Stop Gate 仍需单独完成。

## G. 旧聊天同文攻击的专项用例

在独立 Edge 测试配置中预先创建一条**只有一条与冻结指令完全一致的用户消息**和一条已完成助手回复的旧对话，确保其消息时间早于本轮实验。另创建一个新实验分支，预填、手动点击发送后立即切换到该旧对话，再点击“采集回复”。无论旧对话的指令如何一致，分支均不得变成 done；如果无法可靠确立真实新会话归属，应保持 unknown。这项真实账号用例与 K=2–4 正常成功用例需要同时通过。

## H. Saved Passages 0.2 — 后置真实环境验收

仅在 CF-11 至 CF-15 全部工程实现和自动化门禁完成后执行；当前不启动，不请求用户提供登录凭据。

1. 在真实已登录 ChatGPT 档案中选取不同消息、相同重复文本、跨段落文本和多分支文本，验证本地片段的来源 messageId/nodeId。
2. 在包含多分支的真实对话中切换当前路径与其他可访问叶分支，分别验证历史正文、重点片段高亮、来源跳转、Context Builder 和接续包使用同一条所选路径；断开或不连续的节点路径必须被拒绝。
3. 关闭并重新打开扩展/浏览器，验证 passage 记录和高亮恢复；不得将一个分支的摘录恢复到另一个分支。
4. 对目标消息追加新消息但保持原消息不变，确认 passage 仍可恢复；修改或移除原消息，确认 stale/ambiguous 状态而非静默跳转。
5. 对重复原文制造相同前后文、缺失前后文和单一上下文匹配，验证唯一定位、ambiguous 和 stale 三种结果。
6. ZIP 导出后在另一份独立浏览器配置恢复，验证 passage source identity/hash/offset 与原始消息一致；旧版无 passages 的 ZIP 仍能恢复。
7. Context Builder 分别使用完整消息、仅重点片段、混合模式；核对 passage manifest 回链、附件范围、关键词过滤、预算分段和 stale/ambiguous 阻断。
8. 使用键盘、屏幕放大和真人读屏执行选择、保存、重新定位、跳转、删除及上下文选择；记录焦点、朗读标签、状态播报和错误恢复。

## I. 首次 Edge 实测问题专项复测

以下用例针对 0.2 首轮真实 Edge 测试发现的问题；自动化覆盖不替代本机复测。

1. 打开一条普通历史 ChatGPT 对话，在没有待领取并行实验的情况下，确认页面不出现“并行分支预填未确认（NOT_NEW_NORMAL_CHAT）”提示。
2. 从已保存档案点击“继续这段对话”，确认新聊天在当前 Edge 窗口中以新标签页打开，原始对话和工作区标签页仍保留；不得额外创建 Edge 窗口。
3. 确认新标签页为空白普通聊天后，接续材料逐字预填，附件按校验结果上传；发送仍由用户手动完成。
4. 在新标签页关闭后回到原工作区，确认同时显示“重新采集对话”和“继续这段对话”。
5. 点击“重新采集对话”，确认相同来源、相同保存范围更新原档案；档案数量不增加，既有已保存文件不丢失。更换保存范围时应创建独立档案，不得静默改写原档案的保存范围。
6. 再次打开接续流程，确认旧接续状态不会错误地被新任务复用；来源身份不符合普通新聊天时，显示明确错误且不自动重试。

## J. 2026-11-03 Tabbit 工作界面回归

本节根据用户实际 Tabbit 侧栏使用反馈编制。它定义待执行的真实浏览器验收，不以合成 Chromium CI 替代通过。

| 编号 | 操作 | 通过标准 |
|---|---|---|
| UX-01 | 点击工具栏 ChatFlow 图标 | 默认打开独立浏览器标签页，而非侧栏；关闭标签页不关闭 ChatGPT |
| UX-02 | 开始采集并观察状态变化 | 采集进度按需更新；未变化时 3 秒以上不闪烁、不重建“停止采集”按钮、不丢焦点 |
| UX-03 | 遍历主要操作 | 主操作明显；次要按钮、链接式操作、文件选择入口有一致线框和焦点反馈 |
| UX-04 | 查看主页、设置、归档与连续下载 | 没有重复教学小字；下载完成只更新单条状态，不堆积历史提示 |
| UX-05 | 从首次启动或切回窗口找对话 | 无需点击“刷新”即可发现已打开的 ChatGPT 对话，并保留已有选择 |
| UX-06 | 采集成功、部分成功、失败 | 原 ChatGPT 页面没有采集悬浮条；工作区显示准确的文件状态 |
| UX-07 | 打开接续新聊天 | 仅显示必要的、可关闭的短暂接续提示；不遮挡主要网页操作；发送仍需人工执行 |
| UX-08 | 320、360、480、768、1280px 观察工作区 | 有清楚的文件/整理/接续视觉路径、卡片与边框；无遮挡、无横向溢出 |
| UX-09 | 选择无效 ZIP 两次 | 每次有通俗错误提示；文件选择器清空，原档案仍可读取 |
| UX-10 | 在 Tabbit/Edge 分别下载 CSV、PDF、PNG、XLSX | 记录浏览器默认建议名称与实际落盘名称；若出现随机文件名须保留为待修复，不能仅凭哈希正确写 PASS |

与上一版相比，工程改动包括：移除 manifest 的侧栏声明、采集状态不再注入 ChatGPT 页面、周期刷新改为按状态差异更新、首次/重新聚焦自动发现来源、统一有边框的操作控件与矢量流程图、压缩静态说明和下载状态、优化无效 ZIP 错误、构建生成 JSON/校验清单时统一 LF 字节。是否满足 Tabbit 的实际浏览器扩展行为仍需用户复测。
