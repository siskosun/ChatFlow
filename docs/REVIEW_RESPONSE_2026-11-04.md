# 2026-11-04 代码审查处理范围

审查输入为用户提供的 ChatFlow_Review_2026-11-04.md。以下区分原文发现、源码复核与实施决定，不把推断写成已运行结果。

## 立即处理

- IndexedDB：已复核 passages 索引只在新建 store 时添加；历史升级路径会造成结构差异。必须用真实 IndexedDB 对 fresh、v1、v2、v3、已有 v4 逐条比较。已有 v4 不会重新触发同版本升级；若确认缺索引，需要仅添加缺失索引的 v5 迁移，保留记录、主键和旧归档格式。此必要修复优先于此前“数据库版本不动”的方案偏好。
- Service worker 依赖：TLStore.putPassage 使用 TLPassages，但 worker importScripts 未包含该文件。补依赖，并执行真实加载列表，不以空 importScripts mock 代替。
- 可维护性：本轮修改的控制器按职责拆分、使用可阅读格式；常量建立明确所有者；失败状态保留错误码及操作范围，不记录正文、令牌或签名 URL。
- 测试：保留现有隔离单元测试，同时增加生产入口加载图、实际浏览器、迁移路径、正常和反例样本；不以增加测试文件数量代表覆盖完成。

## 不作机械性改造

- 普通 script 与 importScripts 并不单独构成故障。先验证明确的依赖和加载顺序，不为消除全局名称数字而迁移整个产品技术栈。
- SHA-256 流式实现与 WebCrypto 的用途不同；保留字节级交叉测试，不把存在两个接口直接认定为哈希不一致。
- 旧 src/zip.js、上游采集器等已被 build.py 的运行时白名单排除。它们属于历史审计材料，不属于候选包中的双重 ZIP 运行时。新增打包回归继续验证这一边界。
- 预期取消、幂等清理可以局部捕获；操作失败不能静默消失。区分二者，不把所有 catch 数量当作缺陷数量。
