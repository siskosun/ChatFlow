# ChatFlow 0.3 性能预算

这些门槛用于检测实现退化。样本均为合成数据，不能代替用户电脑、真实 ChatGPT 页面或真实档案库的耗时。

## 固定样本与门槛

| 场景 | 代表样本 | GitHub Actions 门槛 |
| --- | --- | --- |
| 规范化宽分支 | 50,000 节点，49,999 个直接子节点 | 3 次中位数 ≤2,000 ms |
| 规范化长链 | 50,000 节点，完整活动路径 | 3 次中位数 ≤2,000 ms |
| 编译重点片段 | 约 1.3 MiB 快照、1,000 条消息、100 个片段 | 3 次中位数 ≤750 ms |
| 空重点片段编译 | 100 个来源，未选择片段 | 3 次中位数 ≤250 ms |
| 任务列表首次页 | 1,000 个任务、2,000 份结果，正文分别约 2/4 KiB | 首次 ≤1,500 ms |
| 任务列表重复分页 | 同一 IndexedDB 数据库，摘要分页 10 次 | p95 ≤500 ms |
| 任务备份恢复 | 上述完整任务库，逐条格式校验后原子写入 | ≤60 s |
| 档案列表与搜索 | 1,000 份档案，每份正文约 32 KiB，单页 50 条 | 首次 ≤1,500 ms；10 次 p95 ≤500 ms |

Node 基准使用 `node tests/performance.mjs`。实际 IndexedDB 与扩展页面预算在 Chromium 合成测试执行。正文、附件校验与完整备份的费用随数据量增长，不采用固定毫秒承诺；65 MiB 归档回归验证完整往返，不把它当作用户设备速度保证。

## 实现约束

- 快照哈希在一次同步编译的同一来源内计算一次；不使用可能因对象修改而失效的跨调用缓存。
- 父子一致性用集合查询，活动路径一次构造再反转，避免宽分支和长链的二次复杂度。
- 档案、任务与回执具有独立摘要存储。列表读取摘要，正文在打开记录时才读取。数据写入、删除、导入与摘要在同一事务中更新。
- 列表每页有上限，使用游标接续；搜索输入有短防抖。测试除了计时，还拒绝列表路径读取原文 store，避免在快机器上掩盖算法退化。
- 任务备份按记录构造 Blob 并按行读入；校验失败不修改业务记录，成功后原子合并。临时导入空间需要浏览器配额支持。

## 解释与外部验证

预算在固定 Ubuntu 24.04、Node 22、Playwright 1.56.0 CI 环境执行。偶发失败先检查该次负载与数据规模，不直接放宽门槛。报告保存样本大小、运行时、各次耗时和是否通过。

真实账号、大型真实库、真人任务成功率和辅助技术验收在开发与自动化完成后进行。缺少这些样本时应标为未执行，不能将合成库称为真实用户库。
