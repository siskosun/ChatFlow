# ChatFlow Context Builder

Context Builder 从用户明确勾选的本地档案生成可移植上下文包，不调用模型、不自动总结、不自动发送。

## 输入与筛选

- 可同时勾选多份档案；不扫描未勾选来源。
- 默认使用每份档案当前选中的分支路径；档案详情可在当前路径与其他可访问叶分支之间切换。所选路径必须从有效根节点开始、连续且不重复；传入非数组或断开路径会被拒绝。
- 消息按分支图顺序排列，不依赖存储插入顺序。也可显式选择全部可访问分支。
- 可选关键词筛选。多个词必须同时出现在同一条消息或同一条已选片段中；这是确定性文本筛选，不是语义检索。
- 默认不包含原始附件字节。只有显式开启“包含已保存附件”才将经过 SHA-256 复核的文件加入包；相同字节只打包一次，但保留每个来源引用。
- 未保存、损坏、缺失和按范围排除的附件只记录状态和原因，不生成空文件。

## 内容范围

默认 **完整消息**。该模式不会隐式加入调用方提供的重点片段。

**仅重点片段** 只纳入用户明确勾选且当前可定位的原文。没有选中片段或在关键词过滤后没有片段的档案会跳过，并在 `excludedSources` 中记录原因；所有来源均为空时返回明确错误。

**完整消息 + 重点片段** 将完整消息和片段作为不同段落保留。重复片段 ID 被拒绝。选中的片段必须属于所选分支；编译其他分支片段时，需先选择对应路径或显式启用全部可访问分支。

## 来源与定位

每条片段输出 passageId、captureId、conversationId、messageId、nodeId、原文，以及重新解析后的当前 snapshotHash、messageHash、startOffset 和 endOffset。

`anchorAtSave` 同时保留原始保存时的快照哈希、消息哈希和偏移，`resolution` 记录定位依据。这样，原文在同一消息内移动后，不会把新的引用文本与旧偏移混在一起。消息角色改变、原文缺失或无法消歧时，片段不能编译。

从档案页继续对话时，接续包使用相同的所选分支路径，并记录来源对话 ID、快照 SHA-256 和节点路径。准备之后切换分支或更新来源快照，旧接续包失效，需要重新生成。后台在创建目标窗口前再次核验来源快照。

## 输出

- `context_manifest.json`：来源身份与快照、所选分支路径、筛选条件、片段当前与原始锚点、附件状态、完整性、去重/冲突记录，以及被排除来源的原因。
- `context_index.md`：可读索引、分段清单、附件状态和预算提示。
- `context_part_NNN.md`：所选消息或片段的完整文本分段。
- `assets/<sha256>.bin`：仅在用户显式选择包含附件时出现。

`contentHash` 覆盖编译选项、来源、片段、附件记录和文本分段，不包含生成时间。相同输入和选项可以复算；它证明本地产物一致性，不是外部来源真实性证明。

## 预算与验收边界

token 数按字符数除以 4 粗略估算，不声称精确计算。超过预算时完整分段并明确提示，不静默截断；用户需分批上传或缩小范围。

0.2 不自动生成语义摘要，也不会将旧指令提升为当前指令。上下文包是本地文件，不证明网页已经上传、服务端已经接收或模型已经读取。工程回归与真实账号、真人体验验收分别记录，证据见 `PLAN.md`。
