# ChatFlow Context Builder

Context Builder 从用户明确勾选的本地档案生成可移植上下文包，不调用模型、不自动总结、不自动发送。

## 输入与筛选

- 可同时勾选多份档案；不扫描未勾选来源。
- 默认使用每份档案当前选中的分支路径；档案详情可在当前路径与所有可访问叶分支之间切换。Context Builder 记录所选 node path；也可显式改为全部可访问分支。
- 可选关键词短语筛选。多个词必须同时出现在同一条消息中；这是确定性文本筛选，不是语义检索。
- 默认不包含原始附件字节。只有显式开启“包含已保存附件”才将经过 SHA-256 复核的文件加入包；不同档案引用相同 SHA-256 的字节只打包一次，但保留每个来源引用。
- 未保存、损坏、缺失和按范围排除的附件只记录状态和原因，不生成空文件。

## 内容范围

- 默认 **完整消息**，与 0.1 行为兼容。
- **仅重点片段** 只纳入用户明确勾选且锚点仍有效的重点片段；未选中重点片段的档案会跳过，不会让其他来源阻塞编译。
- **完整消息 + 重点片段** 将完整消息和片段作为不同段落保留。
- 重点片段必须属于所选分支；若要编译其他分支的片段，需显式选择全部可访问分支。
- 从档案页继续对话时，接续包也使用相同的所选分支路径，并在 handoff manifest 记录 source conversation ID、snapshot SHA-256 与 branch node IDs。
- passage manifest 记录 passageId、captureId、snapshot/message hash、conversation/message/node、原文与偏移；歧义/过期片段阻止编译。

## 输出

- context_manifest.json：来源档案、conversation/message/node ID、快照哈希、分支模式、筛选条件、附件状态和完整性；分别记录唯一附件字节数与来源引用数。
- context_index.md：可读索引、分段清单、附件状态和预算提示。
- context_part_NNN.md：完整历史文本分段。
- assets/<sha256>.bin：仅在用户显式选择包含附件时出现。

## 预算和完整性

- token 数为字符数除以 4 的粗略估算，不声称精确 tokenization。
- 超出预算时完整分段并明确告警，不静默截断；用户需自行分批上传或缩小筛选范围。
- 同一快照、筛选条件和选项产生可复算的来源快照哈希；改变来源后必须重新生成。
- 摘要/规则提要与原文分开标识；0.1 不自动生成无来源的语义摘要。
- context package 是本地生成文件，不证明 ChatGPT 已上传或已读取全部内容。
