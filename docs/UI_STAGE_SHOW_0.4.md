# ChatFlow 0.4：以任务为中心的界面重排

> 设计方法取自 Benji Taylor 的 [Stageshow 技能](https://github.com/benjitaylor/skills/tree/main/stageshow)（v1.1.0，公开 SKILL.md）。该技能的 React 示例用于**产品演示**；ChatFlow 的实际运行仍采用 Manifest V3、原有 HTML/CSS/JavaScript，不引入 React、动画引擎、第三方网络或扩展权限。
>
> 本文是视觉设计说明，不是独立进度真源。工程进度以仓库 Checkpoint、PR 和准确提交的 CI 为准。

## 设计目标与故事

使用空间：Edge 原生侧边栏，典型宽度 320 / 360 / 520 px，并覆盖桌面 760 px。视觉沿用现行 ChatFlow 的中性蓝灰、系统字体、浅深色模式。

一条完整故事：**选择操作 → 明确来源 → 完成可核对的动作 → 看懂真实状态**。重要数据保持来源绑定；只有用户明确操作才打开新聊天、复制任务或导出 ZIP，不代替用户发送。

四种画面与焦点：

| 画面 | 第一眼应该看到 | 辅助信息 | 收起的信息 |
|---|---|---|---|
| 首页 | “保存并接到新对话”／“任务回传”两条清晰入口 | 必须已登录并打开既有 ChatGPT 对话 | 设备与环境细节 |
| 保存与档案 | 来源、文件范围、保存／继续动作 | 正文与文件实际获得状态，下载备份 | 证据哈希、原始消息 ID、容量与策略参数 |
| 任务回传 | 任务、对应来源、回传结果及下一步 | 原对话标题、创建时间、结果数量 | 后台任务码与会话标识（仍保留在复制的路由协议和备份中） |
| 并行实验 | 任务材料、分支状态、裁决 | 失败与未确认的证据边界 | 实验 ID、修订号、SHA-256、尝试与会话 ID |

## 源自 Stageshow 的设计约束

- “简化文字而不是丢掉产品”：保留真实文件状态、手动操作边界、可访问分支与归属信息；移除只有工程师理解的 ID 拼接。
- “一幅画只讲一件事”：首页用两个同等路径，不用堆叠超大宣传卡；每个子流程只突出当前最重要的动作。
- “先在最终尺寸排版”：320 px 宽度仍保留完整标题、来源名称和按钮；不能截断正在操作的控件。
- “文本层级而非边框数量”：冷白底、轻边框、小间距，数字步骤只用于分组，不给普通元数据添加彩色徽章。
- “反馈与原因一致”：失败对应具体表单或来源操作；未核实上传仍是未知；成功只在获得证据后展示。
- “技术信息按需”：导出/校验所需原始 ID、哈希、任务标记留在数据与高级操作中，普通列表不出现。

参考 Stageshow 金样例：`static-card`（一处明确焦点）、`form-error`（错误贴近原操作）、`ai-chat`（动作结果持续可见）。这是布局与状态叙事的借鉴，**不是从演示代码复制运行时模块**。

## 文案与标识策略

- **不在用户界面拼接** `conversationId.slice(-8)`、`task.code`、`experiment.id`、`revision`、`attempt.id`。
- 两个对话同名时，以“标签页 1／标签页 2”区分；两个任务或实验同名时，在列表中加自然序号，并结合创建日期；实际操作始终绑定原 ID，不按标题猜测归属。
- 对话消息标题显示“我 / ChatGPT / 工具结果 · 第 N 条”；真实消息 ID 仍作为 DOM `data-message-id` 保留，支持精确定位。
- 不认识的内部错误码显示简明中文和可行的重试建议；不会在普通错误横幅直接显示 `HTTP_...` 或 `FF_...`。诊断工具和导出证据仍可保留原始码。
- 外部助手任务文本中的 `[CF-...]` 是可靠回传所需的协议标记，**不擅自破坏**。它只出现在用户明确复制/查看任务文本时，不出现在普通标题与列表中。

## 实际实施范围

- `workspace/flow.js`、`workspace/app.js`：人类可读来源、任务、消息与失败提示；首页布局重排。
- `workspace/style.css`、`workspace/index.html`：一致的字级、宽度、留白、浅深色与窄屏顺序。
- `workspace/experiments.html`、`workspace/experiments.js`：五段进程与收起的技术信息。
- `src/tl-tools-page.js`：导航和导出错误不暴露实现代码。
- 现有的任务归属校验、真实附件取得、未知上传、手动发送、防覆盖和持久化格式**全部不变**。

## 验收

1. 展示样本在 320 / 360 / 760 px 下无水平溢出、标签和按钮不互相遮挡；浅色和深色均可阅读。
2. 来源标题为“继续动力学分析”时，不能产生“继续动力学分析 · e15d7876”这种展示；同名对话仍能分别选择。
3. 任务列表、人工回传来源、历史消息、实验列表、分支进度均不再显示内部 ID 和原始错误码。
4. 在真实安装的合成 Chromium 扩展内执行保存、任务回传、实验与导航既有回归，确保焦点和操作归属不因文案调整失效。
5. 真实已登录 ChatGPT、旧附件和至少 5 名独立首次用户的验证仍是外部门禁，未做不得标为通过。

设计完成不代表正式发布。严格保留现有工程候选与用户验证边界。
