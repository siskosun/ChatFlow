# ChatFlow

ChatFlow 是一款本地优先的 AI 工作连续性浏览器扩展。0.1 聚焦 ChatGPT 对话保存、附件真实字节保全、本地档案恢复，以及向新的普通 ChatGPT 对话安全接续。0.1 仅有 ChatGPT 生产适配器；其他平台不宣称支持。

## 核心流程

1. **保存对话**：选择已打开的 ChatGPT 对话，选择保存范围并保存。
2. **我的档案**：查找档案、检查消息/分支/附件完整性、导出或恢复 ZIP。
3. **继续这段对话**：选择需要的原始附件，生成接续包并打开新的普通聊天。ChatFlow 只预填和附加文件，永不自动发送。
4. **创建上下文包**：从多份档案中筛选当前分支/全部分支与关键词，按预算完整分段，输出来源清单和可选原始附件。
5. **并行对照实验**：冻结同一份材料与任务，开启 2–4 个独立会话，逐个手动发送，采集结果后进行盲测比较与人工裁决。

## 重要边界

- 只采集用户明确选择的对话；实时缓存必须按单个对话明确开启。
- 只有实际非零文件字节通过校验后才显示已保存。
- 保存、ZIP 下载、附件上传和用户发送是不同状态。
- 不覆盖已有草稿，不对未知上传状态自动重试，不自动发送。
- 不删除或修改 ChatGPT 源对话和项目。
- 本地数据保存在当前浏览器配置文件；ZIP 是独立备份。

## 构建

需要 Python 3.12+（仅构建时）：`python build.py`。生成 Chrome/Edge 候选包、BUILD_INFO 和 SHA256SUMS。产品运行不需要 Python、Node、本地服务或云端后端。

## 隐私

不得将真实对话、附件、Cookie、Token、签名 URL 或内部资料提交到公开仓库。真实账号验收只记录脱敏结果。

## 0.1 ZIP 恢复限制

当前版本会在导入 ZIP/ZIP64 之前核验压缩包资源上限：单条目压缩和展开均不得超过 64 MiB，累计展开不得超过 256 MiB，deflate 压缩比例不得超过 200 倍。超限档案将明确拒绝并保留原有本地记录；**能导出 ZIP 不代表该版本能恢复任意大的 ZIP**。后续如需支持超限归档，必须实现带配额检查的分块恢复，不应调高内存上限。

本版本仍为工程候选：真实已登录 ChatGPT、真实文件、5 名独立用户与辅助技术验收未完成。
